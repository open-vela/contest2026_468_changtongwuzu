# 健动跑酷——腕上体感燃脂小游戏

## 项目简介
本作品是一款面向普通智能手表用户的轻量化体感健身2D跑酷快应用，依托手表内置加速度与陀螺仪传感器实现原地慢跑、跳跃、下蹲等肢体动作实时识别，以趣味跑酷游戏形式替代枯燥居家健身，解决大众日常碎片化运动不足、健身难以坚持、居家无器械、锻炼方式单一的问题，实现娱乐与健身双向结合。

## 项目定位与运行环境
本项目为手表快应用专属软件项目，核心运行环境为智能手表操作系统，功能实现完全依赖手表原生传感器与系统接口，无需单片机、嵌入式开发板等硬件载体，全程适配穿戴设备轻量化运行需求，可离线免流量使用。

## 核心功能介绍
### 功能1：原地慢跑体感识别（角色前进核心逻辑）
实时识别原地慢跑动作并驱动游戏角色持续前进。用户停止慢跑后启动3秒缓冲倒计时，期间恢复慢跑即可继续游戏，超时未恢复则触发绊倒判定并扣除1点生命值。


### 功能2：障碍物提前提示与跳跃下蹲避障
游戏场景生成低空、高空障碍物时，会提前展示对应跳跃、下蹲动作提示图标，用户在障碍物抵达角色前完成对应体感动作即可成功避障，未及时完成动作则判定碰撞并扣除1点生命值。


### 功能3：三点生命值与游戏结束机制
游戏初始设置3点生命值，角色发生绊倒、碰撞情况均会扣除1点生命值，生命值清零时自动触发游戏结束机制，结算本局游戏数据，兼顾游戏挑战性与新手容错空间。


### 功能4：2D跑酷场景渲染与碰撞判定
搭建完整动态2D跑酷赛道，渲染游戏角色、各类障碍物及动作提示标识，游戏运行中实时执行轻量化碰撞检测，精准判定碰撞结果，并联动生命值扣除、游戏结束等核心逻辑。


### 功能5：实时计分与卡路里消耗估算
根据游戏存活时长、成功避障次数实时累计游戏得分，同时结合用户运动时长量化估算卡路里消耗，清晰呈现健身成果，所有数据仅作运动参考，非医疗级精准数据。


### 功能6：数据本地存储与历史记录留存
通过本地存储功能保存本局游戏数据、历史最高得分、历史最高卡路里消耗数据，应用重启后数据不丢失，留存用户核心游戏健身记录。


### 功能7：全表盘自适应适配
针对智能手表表盘进行界面适配，优化核心游戏区域布局，保证画面完整居中显示，适配手表穿戴设备屏幕特性。


## 各功能技术方案
本项目为纯端侧本地开发，无云端服务器、无网络请求。所有运算、识别、渲染、存储均在手表端本地完成，低延迟、免流量、可离线使用。

1. **体感动作识别（对应功能1、2）**
部署方式：端侧本地运行。
技术方案：基于手表原生传感器 SDK 实时采集加速度与陀螺仪数据。采用滑动窗口滤波加动态阈值特征识别算法，融合双传感器数据判定慢跑、跳跃、下蹲三类动作。慢跑识别通过垂直轴加速度频域分析，连续检测到 1.5-2.5Hz 周期性波峰达到设定数量且波峰间隔稳定时判定为有效慢跑，同时结合水平轴晃动幅度排除持续性手臂摆动干扰。跳跃识别检测垂直轴单次高幅值向上脉冲（起跳-落地双峰）。下蹲识别检测垂直轴向波谷加持续低幅值区间加陀螺仪俯仰角变化。全部识别本地低功耗运算，无需 AI 模型与云端算力。
所用框架与 SDK：快应用传感器接口、快应用 JS 运行时。

2. **障碍物提示窗口与动作判定联动（对应功能2）**
部署方式：端侧本地运行。
技术方案：游戏主循环根据角色与障碍物相对距离，在障碍物临近时展示跳跃/下蹲提示图标，引导用户完成避障动作，依托传感器实时动作判定联动游戏避障逻辑。
所用框架与 SDK：快应用图片渲染、快应用定时器接口、传感器识别模块。

3. **停止慢跑3秒缓冲与生命值状态机（对应功能1、3）**
部署方式：端侧本地运行。
技术方案：慢跑识别中断时启动 3 秒倒计时缓冲，恢复则取消倒计时继续游戏，超时未恢复触发绊倒并扣一点生命值。基于快应用 JS 框架搭建有限状态机，定义奔跑、跳跃、下蹲、绊倒、碰撞、结束等游戏状态，生命值初始为 3，绊倒或碰撞递减 1，归零时切换至结束状态并结算本局数据。
所用框架与 SDK：快应用 JS 开发框架、快应用定时器接口。

4. **2D画面渲染与碰撞检测（对应功能4）**
部署方式：端侧本地运行。
技术方案：本项目全部游戏场景、角色、障碍物采用图片素材直接渲染，未使用 Canvas 绘图。通过前端布局实现动态场景滚动，配合轻量化矩形碰撞检测实现碰撞判定，适配手表低算力设备，保障游戏基础流畅度。
所用框架与 SDK：快应用基础页面渲染能力。

5. **计分与卡路里估算（对应功能5）**
部署方式：端侧本地运行。
技术方案：得分按存活时长与成功避障次数动态累计。
卡路里计算采用轻量化固定系数算法：**卡路里 ≈ 运动时长（秒） × 0.12**，仅为健身参考估算值，非医疗精准数据。
所用框架与 SDK：快应用定时器接口、本地 JS 运算。

6. **本地数据持久化存储（对应功能6）**
部署方式：端侧本地运行。
技术方案：调用快应用 storage 接口，以 key-value 形式持久化保存**历史最高分、历史最高卡路里**数据。
所用框架与 SDK：快应用 storage 本地存储接口。

7. **多表盘自适应适配（对应功能7）**
部署方式：端侧本地运行。
技术方案：通过快应用屏幕尺寸接口适配**圆形表盘**布局，优化页面边距与元素位置，保证游戏画面居中完整展示。
所用框架与 SDK：快应用屏幕适配接口。

## 已知限制 / 待优化项
1. **无绊倒动画画面**：停止慢跑超时绊倒扣血仅执行后台逻辑，未制作对应的绊倒动态动画展示效果。
2. **无提示延迟补偿机制**：仅实现障碍物临近提示图标展示，未搭建距离-时间映射算法，无法补偿传感器识别延迟与人体反应时间。
3. **生命值无闪烁反馈**：碰撞、绊倒扣除生命值后，仅更新生命值图标数量，无图标闪烁的视觉提示反馈。
4. **未使用 Canvas 绘图**：未采用标准 Canvas 绘图方案，所有游戏场景、角色、障碍物均通过静态图片素材渲染实现。
5. **卡路里计算模型简化**：未采用标准 MET 当量多维计算公式，仅使用固定时长系数计算，数据仅为粗略估算。
6. **本地存储功能精简**：仅支持保存历史最高分、最高卡路里数据，未实现近七日完整游戏记录留存、过期记录自动清理功能。
7. **表盘适配范围有限**：仅完成圆形表盘完美适配，暂未适配方形表盘的UI布局、安全边距与界面自适应效果。

> 补充说明：本项目所有核心体感识别、游戏运行、计分统计、避障交互逻辑均已完整可用。以上内容为本版本功能精简与未完善点，不影响作品完整演示与核心玩法体验。
